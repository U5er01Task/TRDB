## 1. Цель и порядок выполнения работы

**Цель:** освоить трехзвенную методологию проектирования реляционных баз данных (концептуальный, логический и физический уровни), закрепить навыки построения ER-диаграмм, нормализации отношений, назначения типов данных, ограничений целостности и базовых механизмов защиты на уровне СУБД.

**Порядок выполнения:**

1. Ознакомиться с предметной областью согласно номеру своего варианта (раздел 2).
2. **Концептуальный уровень:**
   - Выделить ключевые сущности предметной области (не менее 4–5 сущностей);
   - Определить связи между сущностями и указать мощности связей (1:1, 1:N, M:N);
   - Построить ER-диаграмму в нотации Чена или Crow's Foot.
3. **Логический уровень:**
   - Разрешить связи «многие-ко-многим» (M:N) путем введения ассоциативных сущностей;
   - Определить ключевые атрибуты: естественные и суррогатные первичные ключи (PK), внешние ключи (FK);
   - Проверить структуру на соответствие 1-й, 2-й и 3-й нормальным формам (1НФ, 2НФ, 3НФ);
   - Описать бизнес-ограничения целостности сущностного и ссылочного уровней (NOT NULL, UNIQUE, CHECK).
4. **Физический уровень:**
   - Спроектировать физическую структуру под целевую СУБД (PostgreSQL / MySQL / MS SQL Server);
   - Выбрать точные типы данных для каждого поля с обоснованием экономии памяти;
   - Написать эталонный DDL-скрипт создания таблиц с первичными и внешними ключами, действиями при удалении/обновлении (`ON DELETE / ON UPDATE CASCADE / RESTRICT / SET NULL`);
   - Определить политику индексирования (B-Tree индексы под внешние ключи и частые фильтры);
   - Сформировать требования к безопасности на физическом уровне (ролевой доступ RBAC, маскирование или шифрование чувствительных столбцов).
5. Оформить отчет и ответить на контрольные вопросы.

## 3. Эталонный образец выполнения (Вариант №1: «Студенческий деканат»)

### 3.1. Концептуальный уровень

**Сущности предметной области:**

- `Студент` (Student) — обучающийся колледжа/университета;
- `Академическая группа` (Academic_Group) — учебный коллектив курса;
- `Дисциплина` (Discipline) — учебный предмет по плану специальности;
- `Преподаватель` (Teacher) — педагогический работник, ведущий курс;
- `Аттестационная ведомость` (Exam_Sheet) — документ учета сдачи сессии;
- `Оценка в ведомости` (Grade_Record) — факт выставления оценки конкретному студенту.

**Связи и кардинальности:**

- `Академическая группа` -> `Студент`: один ко многим (1:N);
- `Преподаватель` -> `Дисциплина`: многие ко многим (M:N);
- `Академическая группа` -> `Аттестационная ведомость`: один ко многим (1:N);
- `Дисциплина` -> `Аттестационная ведомость`: один ко многим (1:N);
- `Преподаватель` -> `Аттестационная ведомость`: один ко многим (1:N);
- `Аттестационная ведомость` -> `Оценка в ведомости` <- `Студент`: многие ко многим (M:N, реализовано через ведомость и строки ведомости).

       +------------------+         1:N         +------------------+
       | Academic_Group   |---------------------|     Student      |
       +------------------+                     +------------------+
                | 1                                      | 1
                |                                        |
                | 1:N                                    | 1:N
                v                                        v
       +------------------+         1:N         +------------------+
       |    Exam_Sheet    |---------------------|   Grade_Record   |
       +------------------+                     +------------------+
           ^          ^
           | 1:N      | 1:N
           |          |

  +------------+ +------------+
  | Discipline | | Teacher |
  +------------+ +------------+

### 3.2. Логический уровень

#### Преобразование и нормализация отношений (1НФ -> 2НФ -> 3НФ)

- Все атрибуты содержат атомарные скалярные значения (удовлетворяет **1НФ**).
- Связи M:N разрешены созданием промежуточных таблиц: `Grade_Records` устраняет прямое отношение M:N между студентами и ведомостями; каждый неключевой атрибут функционально полно зависит от первичного ключа (удовлетворяет **2НФ**).
- Отсутствуют транзитивные зависимости неключевых полей: например, специальность группы вынесена за пределы таблицы студента; ФИО и контакты преподавателя не дублируются в ведомостях (удовлетворяет **3НФ**).

#### Логическая схема отношений

1. **Academic_Groups**
   - `group_id` (PK, целое, суррогатный ключ);
   - `group_code` (Естественный бизнес-ключ, уникальный, например, `ИСИП-21-1`);
   - `enrollment_year` (Год набора, целое);
   - `speciality_code` (Шифр специальности, например, `09.02.07`).

2. **Students**
   - `student_id` (PK, целое);
   - `student_card_no` (Номер зачетной книжки / студенческого билета, UNIQUE);
   - `last_name` (Фамилия, NOT NULL);
   - `first_name` (Имя, NOT NULL);
   - `middle_name` (Отчество, NULL);
   - `birth_date` (Дата рождения, NOT NULL);
   - `snils_hash` (Хэш СНИЛС для однозначной идентификации, UNIQUE);
   - `group_id` (FK к `Academic_Groups.group_id`, NOT NULL).

3. **Teachers**
   - `teacher_id` (PK, целое);
   - `tab_number` (Табельный номер сотрудника, UNIQUE, NOT NULL);
   - `full_name` (ФИО преподавателя, NOT NULL);
   - `academic_degree` (Ученая степень/квалификация, NULL).

4. **Disciplines**
   - `discipline_id` (PK, целое);
   - `discipline_code` (Индекс дисциплины по УП, например, `МДК.11.01`, NOT NULL);
   - `discipline_title` (Полное наименование дисциплины, NOT NULL);
   - `total_hours` (Общий объем часов, CHECK > 0).

5. **Exam_Sheets** (Заголовок экзаменационной ведомости)
   - `sheet_id` (PK, целое);
   - `sheet_number` (Номер ведомости в делопроизводстве, UNIQUE, NOT NULL);
   - `issue_date` (Дата выдачи ведомости, DATE, NOT NULL);
   - `semester_no` (Номер семестра, CHECK BETWEEN 1 AND 8);
   - `control_type` (Форма контроля: `Экзамен`, `Диф.зачет`, `Зачет`);
   - `group_id` (FK к `Academic_Groups.group_id`);
   - `discipline_id` (FK к `Disciplines.discipline_id`);
   - `teacher_id` (FK к `Teachers.teacher_id`);
   - `is_closed` (Флаг закрытия ведомости в деканате, BOOLEAN).

6. **Grade_Records** (Строка ведомости — факт аттестации)
   - `record_id` (PK, целое);
   - `sheet_id` (FK к `Exam_Sheets.sheet_id`, NOT NULL);
   - `student_id` (FK к `Students.student_id`, NOT NULL);
   - `grade_value` (Оценка в баллах: 2, 3, 4, 5 или NULL при неявке);
   - `absence_reason` (Причина отсутствия: `Уважительная`, `Неуважительная`, NULL);
   - Бизнес-ограничение: пара `(sheet_id, student_id)` строго уникальна.

### 3.3. Физический уровень (Реализация в PostgreSQL)

#### DDL-скрипт создания схемы базы данных

    -- Создание схемы данных деканата
    CREATE SCHEMA IF NOT EXISTS dekanat;
    SET search_path TO dekanat, public;

    -- 1. Таблица академических групп
    CREATE TABLE academic_groups (
        group_id SERIAL PRIMARY KEY,
        group_code VARCHAR(20) NOT NULL UNIQUE,
        enrollment_year SMALLINT NOT NULL CHECK (enrollment_year >= 2000),
        speciality_code VARCHAR(15) NOT NULL
    );

    -- 2. Таблица студентов
    CREATE TABLE students (
        student_id SERIAL PRIMARY KEY,
        student_card_no VARCHAR(20) NOT NULL UNIQUE,
        last_name VARCHAR(60) NOT NULL,
        first_name VARCHAR(60) NOT NULL,
        middle_name VARCHAR(60),
        birth_date DATE NOT NULL CHECK (birth_date < CURRENT_DATE),
        snils_encrypted BYTEA NOT NULL, -- Зашифрованный СНИЛС (152-ФЗ)
        group_id INT NOT NULL,
        CONSTRAINT fk_students_group
            FOREIGN KEY (group_id)
            REFERENCES academic_groups (group_id)
            ON DELETE RESTRICT
            ON UPDATE CASCADE
    );

    -- 3. Таблица преподавателей
    CREATE TABLE teachers (
        teacher_id SERIAL PRIMARY KEY,
        tab_number VARCHAR(15) NOT NULL UNIQUE,
        full_name VARCHAR(150) NOT NULL,
        academic_degree VARCHAR(50) DEFAULT 'Преподаватель'
    );

    -- 4. Таблица учебных дисциплин
    CREATE TABLE disciplines (
        discipline_id SERIAL PRIMARY KEY,
        discipline_code VARCHAR(15) NOT NULL,
        discipline_title VARCHAR(200) NOT NULL,
        total_hours SMALLINT NOT NULL CHECK (total_hours > 0)
    );

    -- 5. Таблица заголовочной части ведомостей
    CREATE TABLE exam_sheets (
        sheet_id SERIAL PRIMARY KEY,
        sheet_number VARCHAR(30) NOT NULL UNIQUE,
        issue_date DATE NOT NULL DEFAULT CURRENT_DATE,
        semester_no SMALLINT NOT NULL CHECK (semester_no BETWEEN 1 AND 8),
        control_type VARCHAR(20) NOT NULL CHECK (control_type IN ('Экзамен', 'Диф.зачет', 'Зачет')),
        group_id INT NOT NULL REFERENCES academic_groups(group_id) ON DELETE RESTRICT,
        discipline_id INT NOT NULL REFERENCES disciplines(discipline_id) ON DELETE RESTRICT,
        teacher_id INT NOT NULL REFERENCES teachers(teacher_id) ON DELETE RESTRICT,
        is_closed BOOLEAN NOT NULL DEFAULT FALSE
    );

    -- 6. Таблица строк ведомости (оценки)
    CREATE TABLE grade_records (
        record_id BIGSERIAL PRIMARY KEY,
        sheet_id INT NOT NULL REFERENCES exam_sheets(sheet_id) ON DELETE CASCADE,
        student_id INT NOT NULL REFERENCES students(student_id) ON DELETE RESTRICT,
        grade_value SMALLINT CHECK (grade_value BETWEEN 2 AND 5),
        absence_reason VARCHAR(30) CHECK (absence_reason IN ('Уважительная', 'Неуважительная')),
        updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
        CONSTRAINT uq_sheet_student UNIQUE (sheet_id, student_id),
        CONSTRAINT chk_grade_or_absence CHECK (
            (grade_value IS NOT NULL AND absence_reason IS NULL) OR
            (grade_value IS NULL AND absence_reason IS NOT NULL) OR
            (grade_value IS NULL AND absence_reason IS NULL)
        )
    );

#### Индексирование для оптимизации производительности

    -- Индексы на внешние ключи для устранения замедлений при JOIN
    CREATE INDEX idx_students_group_id ON students(group_id);
    CREATE INDEX idx_exam_sheets_group ON exam_sheets(group_id);
    CREATE INDEX idx_exam_sheets_discipline ON exam_sheets(discipline_id);
    CREATE INDEX idx_grade_records_student ON grade_records(student_id);

    -- Составной индекс для быстрого поиска неуспевающих студентов
    CREATE INDEX idx_grades_student_value ON grade_records(student_id, grade_value);

#### Настройка безопасности и разграничения прав доступа (RBAC)

    -- Создание ролей
    CREATE ROLE dekanat_operator;  -- Сотрудник деканата
    CREATE ROLE teacher_role;      -- Преподаватель

    -- Назначение привилегий для оператора деканата (полный ввод студентов и ведомостей)
    GRANT USAGE ON SCHEMA dekanat TO dekanat_operator;
    GRANT SELECT, INSERT, UPDATE ON ALL TABLES IN SCHEMA dekanat TO dekanat_operator;

    -- Назначение привилегий для преподавателя (только чтение списков и выставление оценок)
    GRANT USAGE ON SCHEMA dekanat TO teacher_role;
    GRANT SELECT ON academic_groups, students, disciplines, teachers TO teacher_role;
    GRANT SELECT ON exam_sheets TO teacher_role;
    GRANT SELECT, UPDATE (grade_value, absence_reason, updated_at) ON grade_records TO teacher_role;

| **Целевая аудитория**       | Бизнес-аналитики, заказчики, руководство деканата       | Системные аналитики, архитекторы данных                        | Администраторы баз данных (DBA), backend-разработчики          |

| **Инструментарий**          | ER-диаграммы (нотации Чена, Crow's Foot, IDEF1X)        | Реляционные схемы, таблицы реляционной алгебры                 | SQL DDL-скрипты, планы выполнения EXPLAIN, индексы             |
| **Независимость**           | Не зависит от типа СУБД и аппаратной платформы          | Не зависит от конкретной СУБД (реляционная парадигма)          | Строго привязана к СУБД (PostgreSQL, MySQL, Oracle)            |
| **Реализация безопасности** | Определение критичности сущностей и субъектов доступа   | Проектирование аудита связей и ограничений целостности         | Роли (RBAC), шифрование столбцов (pgcrypto), SSL/TLS, триггеры |
